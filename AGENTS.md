# UniverSR-mod

Fork of woongzip1/UniverSR (MIT, ICASSP 2026): trainable and finetunable on consumer GPUs from user-supplied paired LQ/HQ audio. Same user-facing shell as Emball/Apollo-mod (TUI, configs, run folders, checkpoint names, validation), different backend (flow-matching ConvNeXt U-Net instead of Apollo). Primary experiment: MP3/codec restoration finetuned from the pretrained model.

## Target
- RTX 2080 Ti 11 GB (Turing: fp16 AMP, no bf16), 16 GB system RAM. Ampere+ auto-selects bf16.
- Pretrained base: `woongzip1/universr-audio` (`config.yaml` + `pytorch_model.bin`). Sandbox cannot reach Hugging Face; place files in `models/`.
- The user supplies all data. No synthetic LQ generation in training. `utils/degrade_audio.py` stays as a manual tool.

## Pretrained model facts
- Mono, 48 kHz, STFT n_fft 1024 / hop 512, 512 bins (Nyquist dropped), amplitude-compressed (alpha 0.2) complex STFT as 2 real channels.
- Condition path: low bins -> FiLM(freq pos-emb) -> ConvNeXt blocks -> mean over frequency -> one vector per frame. The U-Net never sees bin-aligned condition.
- Generated region is always bins 80-511 (432). Upstream discards the part overlapping the condition at assembly.
- Input bandwidth is a 4-row table (8/12/16/24 kHz -> 80/128/170/256 bins) with a 4-row embedding. MP3 lowpass (16-20 kHz) is beyond the trained range.
- Trained on peak-normalised audio (random -1 to -6 dBFS), 32767-sample crops; 10% condition dropout for CFG; sampling 4-step midpoint, upstream guidance 1.5. Our configs use `system.val_guidance: 1.0` (plain conditional prediction; the unconditional pass is skipped at 1 and at 0, where 0 means guidance off, not unconditional): at 1.5 the extrapolation past the bin-aligned condition added a loud 1-12 kHz band that training never sees.

## Apollo-mod contract (the TUI depends on it)
- CLI: `core/train.py --conf_dir X [--resume] [--weights_path P]`, `core/inference.py --in_wav --out_wav --weights --conf_dir`, `core/evaluate.py --conf_dir`.
- `configs/*.yaml` with `exp.name`/`exp.dir`; runs in `runs/<name>/<timestamp>/checkpoints/*.ckpt`.
- Checkpoint name `step={:06d}-sisdr={:.3f}-visqol={:.3f}-hfnr={:.3f}`; best = `(visqol, sisdr, -hfnr)`.
- `PAUSED` sentinel in `runs/<name>/` suspends training; Ctrl+C saves a checkpoint.
- Data: `data/<name>/{train,val}/{LQ,HQ}` -> chunk cache under `usr/cache/chunks/<key>/`; two 10 s highest-RMS val clips per song, locked and rotated.

## Design decisions
- Pairs are resampled once at chunk-cache time to `datas.sr` (same filter for LQ and HQ; no-op when files already match). `datas.sr` must equal `transform.sampling_rate`. `configs/universr_stfl2.yaml` is native 44.1 kHz: n_fft 960, hop 480, `total_freq_bins` 480 (0-22.05 kHz, 45.9 Hz and 10.9 ms per bin/frame vs 46.9 Hz and 10.7 ms pretrained), crop 30719 samples (64 frames). `configs/universr_stfl_new.yaml` and the pretrained config stay at 48 kHz (1024/512, 512 bins). `exp.data` optionally points a config at another data folder. A run folder trained with a different bin count cannot be resumed. `total_freq_bins - gen_start_bin` must be a multiple of 16 (the U-Net strides). Default bandwidth anchors are the 8 defaults with the last one set to `total_freq_bins`. The loader slices `freq_pos_enc.pe` (a fixed sinusoid) when the checkpoint has more rows. `weights_path` may be a Lightning `.ckpt` (EMA weights, fresh optimizer): that is how a run is warm-started from another run. ViSQOL audio mode needs 48 kHz, so `metrics.visqol` resamples est and ref internally; training never sees that.
- Lightning shell with plain OmegaConf config loading (no Hydra); backend is `core/universr/` (replaces `core/look2hear/`).
- Level handling matches upstream (song-level peak, then crop): chunks are cached with the pair-shared song peak at `datas.cache_peak_dbfs` (-1). At load, a relative gain puts the song peak at a random -6..-1 dBFS (train) or -3 dBFS (val); crops are never renormalised, so quiet passages stay quiet. Inference restores the original level.
- Stereo: as Apollo-mod. Training sees single channels via the `stereo_alternation` augmentation (L first half of a song, R second half; skipped when `mid_side_isolation` fires). Inference processes L and R independently and re-stacks them; shared noise across channels is an optional flag, off by default.
- Conditioning generalised to per-sample bandwidth: embedding interpolated between anchor rows (first four = pretrained rows), masked mean over valid bins.
- Repair path (arm C): bin-aligned degraded spectrum + validity mask as extra `init_conv` input channels over the generated region, zero-initialised. Generated region can start at bin 80 (default) or 0.
- Assembly: arm B keeps real bins up to the cutoff; arm C takes generated bins from the generated-region start.
- Flow-matching loss is uniform across frequency in the shipped configs; per-Hz band weights (`system.band_weights`) remain supported in code but are unset.
- GAN discriminator and its losses are not ported. Apollo optimizer factory (adamw, 8-bit, gefen, gefen_muon), grad accumulation, checkpointing, RAM watchdog, augmentations, spectral-merge ensemble are.
- Arms on the same held-out set: A zero-shot pretrained (baseline val pass; real bins kept below cutoff), B cutoff-aware finetune, C B + aligned channels. Metrics: ViSQOL, LSD-high, HFNR, SI-SDR; SI-SDR is expected to trail for a generative model.

## Phases
0. Fork, AGENTS.md, VERSION.
1. Restructure to Apollo layout (`core/`, `utils/`, `configs/`, `models/`, `runs/`); port TUI, degrade/align tools, launchers; remove upstream-only entry points. Done: upstream train/evaluate/dataset kept in `core/_upstream/` as reference until phases 2-5 replace them; TUI is a verbatim copy pending phase 8 deltas.
2. Data: port paired datamodule and chunk/val-clip prep at 48 kHz; mono crops; level handling; augmentations (live + cached). Done: `core/{audio_io,augment,cutoff,data_prep,paired_datamodule}.py`. Cache keys include sample rate and alignment. Delays (`align_data`) are in samples of the file being trimmed, applied before resampling. All resampling goes through `audio_io.resample`. Per-sample cutoff comes from `datas.cutoff_hz` (`auto` | Hz | [min,max]); `auto` detects the spectral drop on the augmented LQ, so live `noise` augmentation defeats it.
3. Backend: cutoff-aware conditioning, aligned channels, region config, pretrained loader with shape reconciliation; CPU step-0 equivalence test against original U-Net. Done: `core/universr/models/{unet_mod,loader}.py`, `tests/test_model_equivalence.py` (CPU; matches the original U-Net to ~4e-7 at step 0 for arms B and C, conditional and unconditional). API: `forward(x, t, y, cutoff_bins)`; `y` is the LQ spec from bin 0 (arm C also reads bins from `gen_start_bin` up); `cutoff_bins` is per sample; `y=None` is unconditional. Bandwidth anchors default to (80,128,170,256,341,405,470,512); the pretrained 4-row table is interpolated onto them. Per-block checkpointing is in the model (`grad_checkpoint`). In mixed-cutoff batches, samples narrower than the batch max differ slightly from a standalone run (zero vs reflect padding at the cutoff edge, up to ~4% of output scale at 80 bins); uniform cutoffs or per-sample runs are exact.
4. LightningModule: flow-matching step (fp32 STFT, AMP), band weights, accumulation, clipping, block checkpointing, ODE validation with locking/rotation, baseline cache. Done: `core/universr/{system,sampling,metrics}.py`, `flow/loss.py`, tests in `tests/` (CPU, Lightning end to end). `UniverSRSystem` uses automatic optimization: accumulation, clipping and precision are Trainer args; the optimizer and a step scheduler are passed in; the network is `audio_model`. It logs `train_loss`, `sisdr` (real SI-SDR, higher is better), `hfnr`, `visqol` (-1 if unavailable), `lsd_high`, `val_cfm`. Validation runs the ODE sampler (midpoint, CFG, per-clip seed) on every clip of the `val_songs` songs in the active window; the window rotates every `val_rotate_every` steps (`auto` = max_steps / windows); song order, window index and EMA are saved in checkpoints. `ema_decay` > 0 keeps an EMA that is swapped in for validation and stored under `ema` in checkpoints. Per-band loss weights: `band_weights: [{lo_hz, hi_hz, weight}]`. Preview WAVs go to `val_audio_dir/step_N`. The baseline pass is `trainer.validate` on the pretrained weights, cached by train.py.
5. `train.py` port. Done: `core/{train,train_opt,ckpt_utils}.py`. Run folders, StepPrinter, `PAUSED`, step-based resume with config reconcile (`.resume_reconciled.ckpt`), baseline pass cached under `usr/cache/baseline/` (it always writes `val_audio/step_000000`: on a cache hit the pass is re-run for audio when that folder is missing), `best_model.pth` export (EMA preferred). Ctrl+C saves `step=N.ckpt` at the next training step (second press quits without saving); that file is never ranked best. `ckpt_utils` owns filename parsing and the `(visqol, sisdr, -hfnr)` ranking (ViSQOL -1 ranks last; SI-SDR is not sign-flipped). `train_opt` has the optimizer factory (adamw, 8-bit, gefen, gefen_muon via a `torch.optim.Optimizer` subclass), step scheduler, freezing by name prefix, RAM watchdog and precision auto-select (fp16 below compute capability 8.0, else bf16). Epochs are trimmed to a multiple of `grad_accum_steps` so `val_check_interval` (optimizer steps) stays aligned with global_step. `EMA` weights are swapped in for validation and restored before the checkpoint is written. Verified on the 2080 Ti: fp16 training, validation, ViSQOL, baseline pass, VRAM. Untested on real hardware: resume, Ctrl+C, 8-bit/gefen optimizers.
6. Inference and evaluate. Done: `core/{restorer,ensemble,inference,evaluate}.py`. `restorer.load_restorer(weights, conf_dir)` accepts a Lightning `.ckpt` (needs the config; EMA applied), the exported `best_model.pth` (self-describing, no config needed), a pretrained `.bin`, or `pretrained`; with no weights and a config it picks the best ranked checkpoint across the experiment's runs. `restore_audio` handles one file: decode, resample to the model rate, scale the song peak to -3 dBFS for the model and restore the original level afterwards, cutoff (`auto` detects the spectral drop of the input, or a fixed Hz), channels restored independently (separate seeds unless `--shared_noise`), chunked overlap-add (`restore_long`, ramps only at chunk overlaps so file edges keep full weight), optional spectral merge and aux-checkpoint blend (`ensemble.py`, Apollo semantics: phase from the enhanced signal, magnitudes blended per band). Output is 32-bit float WAV at the model rate, or the input rate with `--match_input_sr`. `inference.py` keeps the Apollo flag contract the TUI uses (`--in_wav --out_wav --weights --conf_dir --chunk_sec --overlap_sec --device --low_end_preserve --low_end_hz --ensemble --aux_*`) plus `--cutoff_hz --steps --guidance --seed --shared_noise --precision --match_input_sr`. `evaluate.py` keeps `run_evaluation`, `print_results_table` and `screen_evaluate`; it runs every checkpoint on the same fixed val clips (equal share per song, `training.eval_clips` or `--limit`), ignores the rotating-window numbers in filenames, caches per file and settings in `<ckpt_dir>/.eval_cache.json`, ranks by composite (visqol .60, hfnr .25, sisdr .15), and `--baseline` adds the zero-shot pretrained model with real bins kept below the cutoff. Untested (written without running, by request): all of phase 6, TUI call sites for the new flags.
7. Configs. Done: one config tailored to the target machine, `configs/universr_stfl2.yaml` (data in `data/universr_stfl2/`), mapped from Apollo-mod's `apollo_stfl2` (no VRAM tiers). It is arm C (`model.aligned_input: true`; set false for arm B). Mapping: AdamW wd 0.01, lr 3e-5 with `optimizer.lr_mult` 3 on `init_conv.` and `bw_embedder.` (started at 1e-5, the Apollo `lr_g`, raised when ViSQOL gains flattened); `freeze: []` (it began as `[encoders.0., encoders.1.]`, standing in for freezing 4 of 6 Apollo layers, but those stages are 2.7% of the parameters); Apollo's StepLR(2, 0.98) is replaced by constant lr after 200 warmup steps because this scheduler steps per optimizer step; Apollo's band weighting and target band are not ported (uniform loss); augmentations are copied; `val_songs` 6, `val_rotate_every` 20000, `val_check_interval` 200 in every config. `gen_start_bin: 80` keeps step 0 identical to the released model; 0 would also generate bins 0-79. `batch_size: 4` with `grad_checkpoint: true` measured on the 2080 Ti: ~7 GB reserved while training, 1.4 to 1.6 it/s, ~90 s per validation. `datas.cutoff_hz: 24000` (full band) in both configs. Second config `configs/universr_stfl_new.yaml` ports Apollo's `apollo_stfl_new.yaml` (data in `data/universr_stfl_new/`): same keys minus `band_weights`, `val_check_interval` 200, and `freeze: []` (it began as `[encoders., midcoder., decoders.]`, the closest analogue of freezing all pretrained layers; `extra_layers` has no UniverSR equivalent). `system.band_weights` entries are either `{lo_hz, hi_hz, weight}` (later override) or `{shape: gaussian, center_hz, sigma_hz, gain}` (adds `gain*exp(-0.5*((f-c)/sigma)^2)` to the current weight, Apollo semantics). Not implemented: memory profiler utility.
8. TUI deltas, launchers, smoke tests. Done (written without running): `utils/tui.py` has the UniverSR banner, no `--feature_dim` (inference.py rejects unknown flags), lists only configs with an `exp` section (`universr_pretrained.yaml` is a reference file the restorer reads), a `_pick_restore_options` menu for `--cutoff_hz/--match_input_sr/--shared_noise`, and a 15-24 kHz transition-blend preset. `universr.sh`/`universr.bat`: `train|inference|evaluate` map to `core/`, both self-update with `git pull --ff-only` and strip `--dev`. `requirements.txt` has no torch pins (launchers install torch 2.7.1 cu126) and no unused hydra-core/torch-optimizer/fast-bss-eval/python_box. `tests/SMOKE.md` lists the checks that must run on the GPU machine; none has run yet. Remnants not on the active import path: `core/universr/{trainer,inference.py,flow/solver.py,utils/{utils,logger}.py}` (need wandb/box/torchdiffeq).

## Performance notes
- `ConvNeXtUNetCondMod(fast_ops=True)` swaps in `FastGRN`/`FastLayerNorm` (same maths and parameters; the original GRN promoted its 4x-wide activation to fp32 under AMP). `channels_last` is an optional NHWC mode, default off until benchmarked. Both are `model:` config keys.
- Validation restores clips in `system.val_chunk_sec` chunks (4 s); a whole 10 s clip needed ~10 GB VRAM.
- The baseline cache key hashes every `core/**/*.py` source file plus the resolved model/transform/system/datas config, so any code or parameter change re-runs it (also on resume, using the pretrained weights); the baseline numbers print beside the live ones in the step line as `(base X)`. On resume the config's `optimizer.lr` (and `lr_mult`) overrides the lr stored in the checkpoint (`ConfigLR` callback); Lightning would otherwise restore the old one silently. `universr/memlog.py` logs `[mem]` lines (torch alloc/reserved/peak, driver VRAM, allocator retries, RSS) at train start, every `system.mem_log_every` steps, validation start/end and every restore chunk (`system.mem_log`, off by default). `val_cfm` is computed on a centered `val_chunk_sec` crop, not the whole clip. Resuming runs one validation of the checkpoint before training (audio in `val_audio/step_<ckpt step>`).
- The first real run on the 2080 Ti (batch 8, original GRN) crawled at ~0.2 it/s with all-empty baseline metrics and system RAM near 16 GB; the cause was fp32 promotion in GRN plus an fp16 overflow in the pretrained net, fixed by `fast_ops` and `fp32_modules`. The progress line shows `loss` and `data` (% of time waiting on the dataloader). `tests/bench_gpu.py` times model variants and locates the first non-finite module in fp16.

- Non-finite loss: `system._check_finite` runs `diagnose.run` once (per-module trace under autocast and fp32, plus input checks, logged as `[nan-diag]`) and aborts after 25 consecutive non-finite losses. `model.fp32_modules` (submodule paths, every leaf under each) runs those modules with autocast off; default `encoders.3.blocks` + `midcoder` because the pretrained net's activations reach ~1e5 in `encoders.3` (measured), above the fp16 max of 65504. The conditioning encoder's frequency mean is computed in fp32.

- Full-band conditioning: configs set `datas.cutoff_hz: 24000` (every LQ bin valid; the mask is all ones) because iTunes-MP3 damage is wideband and the specks above the lowpass carry information. `system.lsd_cutoff_hz` (16000) defines the LSD region instead of the model cutoff. `inference.py` defaults `--cutoff_hz` to the config's `datas.cutoff_hz`. `optimizer.lr_mult` ({prefix: factor}, adamw/adamw_8bit) boosts the lr of the aligned channels (`init_conv.`) and `bw_embedder.`.

- Loss and validation options (`system:`): `alpha_start` + `alpha_anneal_steps` slide the compression exponent from `alpha_start` to `transform.alpha` over that many steps, counted from the step a run starts or resumes at (`alpha_origin` and the current `alpha` are saved in checkpoints; the restorer and `best_model.pth` use the saved alpha; the baseline and any pre-training validation run at `alpha_start`). Resume from a checkpoint trained at `alpha_start`: resuming from one already at the final alpha restarts the anneal. `t_skew` p maps t = 1-(1-u)^p (p > 1 favours the clean end). `aux_logmag_weight` adds t^2-weighted squared ln-magnitude error (decoded-magnitude units) of the one-step estimate x1_hat = xt + (1-t) v, uniform over bins. Validation prints a `[bands]` line (mean per-bin dB of restored minus HQ over 3.75-8, 8-12, 12-16, 16-22 kHz) with the baseline beside it.

## Upstream training distribution (keep data matched)
- Samples are random 32767-sample crops (~0.68 s, `num_samples`) of whole files, one per file per epoch, mean-downmixed to mono. We crop from cached 3 s chunks at 50% overlap (every crop fits inside some chunk) and take a single channel via `stereo_alternation`.
- Upstream draws one bandwidth per batch; we use a per-sample cutoff in Hz.
- Upstream val is the first 5 s of each file; ours is two 10 s highest-RMS clips per song (ViSQOL-compliant).

## STFT facts
- The transform's Hann window is symmetric (zero at both ends). Inverting a modified spectrum divides by a near-zero envelope in the last <hop samples unless the length is a multiple of the hop, so every inversion path uses `to_spec(..., pad_to_hop=True)` and `to_wave` (natural length, then crop). Training keeps upstream framing (no pad; 32767 samples = 64 frames).
- Sampling uses `sampling.py` (own midpoint solver); `torchdiffeq` is only needed by `core/_upstream/`. WAVs are written with soundfile (`audio_io.save_wav_f32`) because torchaudio >= 2.9 needs TorchCodec for I/O.

## Running
```bash
universr.bat            # or ./universr.sh: TUI
universr.bat train --conf_dir configs/universr_stfl2.yaml [--resume] [--weights_path P]
universr.bat inference --in_wav in.wav --out_wav out.wav --conf_dir configs/universr_stfl2.yaml
universr.bat evaluate --conf_dir configs/universr_stfl2.yaml [--baseline]
```

## Config keys (present in every experiment config)
- `checkpoint` monitor is always `visqol`; `save_top_k=-1` (all checkpoints kept).
- `training.val_songs`, `val_rotate_every`, `val_check_interval` (200), `limit_val_batches` always present.
- All augmentation keys present even when disabled.
- `system.mem_log` present and `false` by default.
- `model.fp32_modules` present; default `[encoders.3.blocks, midcoder]`.
